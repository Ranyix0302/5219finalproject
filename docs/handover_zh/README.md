# GE5219 MCDA 交接主说明（中文版）

文档日期：2026-10-19。本文面向第一次接触 MCDA 的组员，可独立阅读。英文完整版本见 [English handover](../handover_en/README.md)。文中“实际结果”均来自包内冻结文件；“教学假设”另有明确标记。

**本项目交付的是一个可复算、可解释的住宅位置比较基线。** 它回答：在已交付住宅记录、指定 NUS AS8 路由场景、七项指标和声明偏好下，哪些官方 Subzones 的已验证可行代表位置平均分最高？它没有核验当前租房供应、租金、住户容量或所有设施开放情况，因此不能直接回答“学生现在应该租哪一套房”。

## 0. 先用日常语言理解整条链路

先测量每个代表住宅点的七项条件，再用同一把0–1尺子比较，按偏好权重相加，排除不满足硬约束的位置，最后汇总成官方分区的推荐。敏感性分析再问：换偏好、换上限或换空间单元，推荐会怎样变？

- **当前是否用了decay？** 没有。公交站、超市和诊所用固定半径计数；MRT／图书馆用最近直线距离；公园用到公园面的直线距离；校园用OneMap返回的首条行程时长。距离衰减目前只是可讨论的扩展。
- **P5、P95是什么？** 把某一指标的有效数值由小到大排列，找约5%与95%位置的分界值。它们是原值的分位数，不是权重，也不是“5分、95分”。
- **裁剪是什么？** 为了计算分数，暂把两端过于极端的值按分界值处理。公交P95是48，因此57站暂按48站换算得1分；原始57站和整条住宅记录都保留。
- **Monte Carlo在问什么？** 假如大家对七个方面的重要性判断有所不同，推荐还会不会差不多？本版随机生成1,000组合法权重并逐组重排，不重新抽住宅，也不重新请求路线。
- **OAT在问什么？** 如果逐步提高“校园”这一项的权重，哪些地区会进入或退出前5？其余六项要按比例让出份额，权重总和仍为1。
- **组员怎么调用？** 现有Python与命令行接口可重新评分、自定义权重和设置通勤上限；Python还可改区域资格门槛、Top k等。见[接口使用说明](interfaces.md)。当前没有已部署的HTTP服务，也没有任意设施距离硬约束。

下文的图都紧跟所解释的文字。每幅图注明“真实结果”或“教学示意”，并给出颜色／线条图例、坐标轴含义和读法。

## 2. A、B 原始交付提供了什么，为什么不能直接叠加

A 提供住宅与设施等 GIS 图层；B 提供已经合并的住宅主表、轨交出口和公交站数据，以及少量路由演示。这里的“原始交付 A/B”是组员的数据来源；后文的“样本 A/B”是本项目建立的两个采样集合，不能混为一谈。

原始 A 的 Dwelling 与 HDB 层合计 96,977 条，B 的合并住宅主表也是 96,977 条。B 已经包含这些住宅，再追加一次 A 会重复计数。实现从 B 的冻结表开始，映射 A 的来源层、对象 ID、六位邮编和校验信息，保留 B 的坐标。实际来源映射失败数为 0。

| 来源住宅类型 | 原始记录 | 当前纳入候选 | 解释 |
| --- | ---: | ---: | --- |
| HDB | 13,436 | 13,329 | 保留 HDB 标签；点或面不自动等于真实 estate |
| Landed | 73,041 | 72,934 | 大量地址点不等于大量学生可租机会 |
| Non-Landed | 9,897 | 9,897 | 不擅自改称全部已经核验的 condo |

96,977 条记录只有 96,870 个唯一邮编，其中 **107 个邮编组各有两条跨来源冲突记录，共 214 条**。当前两侧都暂缓，等待 A/B 核准；没有默认相信 HDB 或私人住宅的其中一个坐标。因此 `96,977 − 214 = 96,763`。这是公开的保守处理规则，不是宣称 214 条都无效。真实冲突和暂缓列表见 [postal_conflicts.csv](../../outputs/prepared/audits/postal_conflicts.csv) 与 [held_out_residences.csv](../../outputs/prepared/audits/held_out_residences.csv)。

**同坐标也不能盲删。** 不同邮编可能被地理编码到同一个建筑代表点，原始数据的共址组甚至有 38 条住宅记录。相同坐标能共享路由缓存，却不能单独证明它们是同一个地址、同一住户或重复住宅。内部 `building_id` 标识带版本的来源记录，`location_id` 标识分析位置，均不构成“每条必定对应一栋独立物理楼宇”的认证。

A 与 B 的住宅点生成方式存在差异。全量来源映射中的坐标差异 P95 约为 9.08 m，最大约 83.43 m；将 A 坐标覆盖到 B 上却继续使用 B 的旧距离，会造成同一行数据含义不一致。因此本版保留 B 坐标，记录差异，再从源设施重新计算静态指标。原始 B 的校园演示只有 **5 个不同住宅到 AS8 的案例**，不是覆盖全岛的通勤矩阵；多个导出格式也不是新增独立路线。

这 5 个旧演示的行程时长实际为 58.28–97.32 分钟，全部超过 40 分钟，但仅凭它们不能推断“全岛没有 40 分钟内住宅”。当前 2,196 个冻结起点的完整查询才支撑本版评分的通勤列。住宅源约四分之三为 Landed，这种地址记录构成也不能解释为四分之三学生租房供给。

这些记录的住宅用途仍主要依赖源分类。尚未证明住宅清单完整、每条当前在用、允许学生租住或正在出租；项目没有把 URA 规划住宅用地自动当成已存在住宅候选。数据处理成功与来源已经完全认证是两件不同的事。

## 3. 几何、设施和地址：先决定“在数什么”

所有米数、半径和聚类在 **EPSG:3414** 新加坡投影中计算；经纬度与显示 GeoJSON 使用 **EPSG:4326**。不能直接用经纬度差当米数。6 条无效 Subzone 面、2 条无效公园面只在派生副本中修复，并保存前后几何类型和面积审计。住宅先匹配严格内部；边界或重叠的并列匹配按官方代码字典序确定，并保存所有相交代码。当前候选没有点落在所有 Subzones 之外；规则仍保留这种未知情况，不强行归到最近分区。

设施计数也必须先规定单位。诊所的 1,192 条许可证经服务地址规则变成 1,186 个站点；超市 440 条源记录保留为 440 个站点。一个站点是标准化的**邮编＋街道地址＋楼层＋单元号**，不等于一张许可证，也不等于一个坐标。

教学地址例子：同一完整地址 `123456 / EXAMPLE ROAD / 02 / 03` 的两张许可证可合并为一个服务地址；同楼层的 `02-04` 则是另一地址，即使地图点重合。楼层或单元缺失、单元为 `0`、疑似电子表格转换产生的长数字，均不能证明许可证属于同一服务单元；它们以许可证为键保留并标记待核准，不从建筑名称猜单元。组内坐标跨度超过 20 m 是复核提示，代表点按许可证字典序固定选择；20 m 不是精度合格证。

冻结规则为 `complete-service-address-v2`。目前诊所 59 个、超市 99 个站点仍是地址未解决的保留记录；超市有 116 条地址审阅标记，标记数与未解决站点数含义不同。它们不能被称为已经确认互不重复且正常运营的服务机会。一次真实静态复核已发现并修复医院缺楼层字段时被错误合并的问题，诊所数由旧计算 1,185 改为当前 1,186；当前数据版本已经包含修复。追踪表见 [诊所映射](../../outputs/prepared/audits/clinic_licence_site_mapping.csv) 和 [超市映射](../../outputs/prepared/audits/supermarket_licence_site_mapping.csv)。

交通源数据没有完整运营状态。613 个 MRT/LRT 出口中，本版依据 2026-10-17 的部分审查排除 MARINA SOUTH MRT STATION 的 4 个未开放出口，保留 609 个；MARINA SOUTH PIER 是另一站。该排除对本版 2,196 个位置的最近出口距离影响为 0，仍应保留正确运营规则。其余 609 个出口、5,205 个公交站点尚未逐个认证运营，临时关口、班次、拥挤和服务频率也未测量。[运营审查快照](../../outputs/prepared/transit_operation.json) 记录当时依据，不能当作今天全网状态的实时证明。

公园有 462 个源面，其中源字段 `N_RESERVE=1` 的 7 个面按冻结规则排除，暂纳入 455 个面。这个 7 是**源标记面数**，不是法律定义上 7 个不同自然保护区；其余公园、走廊类别和公众开放仍需核准。原始 462 个公园 centroid 中有 52 个在自身面外；即使 centroid 在面内，它也不是入口。本版使用公园面距离，住宅点在面内时取 0，但这不证明附近有可进入的门、合法通道或开放时间。更详细处理见 [空间数据说明](../spatial-data-notes.md)。

## 4. 从 96,763 条住宅记录变成可计算的代表位置

逐条查询近十万个住宅的指定时间路线成本较高，本版先用公开、固定的空间规则采样，不按设施得分预筛。EPSG:3414 网格原点固定 `(0,0)`、边长 400 m。每个有住宅的“网格格子 × Subzone”选距格子中心最近的**真实住宅记录**，距离并列按稳定 `building_id`。这样跨边界的一格可有两个分区各自的代表点，避免整个小分区被相邻分区吞掉。原样本 A 得到 **2,176 个位置**，覆盖 241 个有候选住宅的官方 Subzones。

cluster 由全量 96,763 条候选住宅在每个 Subzone 内建立：两点直线距离 `≤150 m` 就连边，取无向图连通分量；单点也保留。得到 **384 个分析簇，其中 44 个单点簇**。这是研究用连接规则，不是真实 estate、居住社区或物业边界。

教学链条例子：住宅甲距乙 140 m，乙距丙 140 m，甲距丙 280 m，三者仍在一个 cluster。因此“150 m cluster”不意味着每个成员都距中心 150 m 内，长链可以跨越远大于 150 m 的范围。完整簇表的 `extent_diagonal_m` 是投影坐标轴对齐包围盒对角线，用于显示尺度；不是实测最大点对距离，也不是 estate 边界。

实际最大成员簇为 FRANKEL `BDSZ05_C_0fe53e56a96e`：6,124 条候选记录、包围盒对角线约 3,619.64 m，A/B 均有 34 个代表点。这说明链连接的尺度问题真实存在，不能把“150 m”当成每个簇的小范围保证。

A 未覆盖 20 个小簇，于是样本 B 为 A 加上每个漏簇中距成员点均值中心最近的一个真实住宅，得到 **2,196 个位置**。补点独立于设施分数和路线成功；不补造 centroid 住宅，也不把一个位置的分数复制给全簇每栋楼。保证“每簇有计划位置”不能证明“每簇已得到充分代表”。[analysis_locations.csv](../../outputs/prepared/analysis_locations.csv) 保存 `sample_A` 和选择原因，[clusters.csv](../../outputs/prepared/clusters.csv) 保存全量成员支持。

## 5. 七项指标分别测量什么

MCDA 是 Multi-Criteria Decision Analysis，多准则决策分析。这里可先把它理解成：将七种不同单位的测量变成同向的 0–1 表现值，再按声明的重要性相加。关键不是把数字凑成一个分数，而是知道每一列究竟代表什么。

设住宅位置为 `p_i`，`d(p,q)` 为 EPSG:3414 欧氏距离，`1[条件]` 为条件满足时取 1、否则取 0。点集合已按冻结规则整理，计数半径包含边界。

| 指标／字段 | 精确定义与方向 | 生活含义及没有测量的内容 |
| --- | --- | --- |
| 校园行程 `campus_transit_min` | `t_i = 第一条 OneMap itinerary.duration / 60`，分钟，越小越好（cost） | 指定场景到 AS8 的提供者计划行程；可含纯步行，初始排程等待可能不在 duration 内，详见第 11 节 |
| 轨交出口 `rail_exit_euclid_m` | `r_i = min_q d(p_i,q)`，q 为保留 MRT/LRT 出口，米，越小越好 | 出口邻近性；不是走路路径、走路分钟或保证运营 |
| 公交站 `bus_stops_800m` | `b_i = Σ_q 1[d(p_i,q) ≤ 800]`，站点数，越大越好（benefit） | 周围站点数量；不是独立线路数、班次、运力或到校服务数 |
| 超市 `supermarket_sites_800m` | `s_i = Σ_q 1[d(p_i,q) ≤ 800]`，服务地址数，越大越好 | 日常购物选择的邻近代理；没有价格、规模、营业时段或库存 |
| 图书馆 `library_euclid_m` | `l_i = min_q d(p_i,q)`，q 为交付图书馆点，米，越小越好 | 最近图书馆邻近性；没有座位、预约、开放时间或网络步行距离 |
| 诊所 `clinic_sites_1000m` | `c_i = Σ_q 1[d(p_i,q) ≤ 1000]`，服务地址数，越大越好 | 医疗服务邻近选择；不代表质量、价格、学生适用性或急诊能力 |
| 公园 `park_proximity_euclid_m` | `g_i = min_{q∈公园面并集} d(p_i,q)`，面内为 0，米，越小越好 | 纳入绿地的几何邻近性；不是入口距离、可步行通道、公众进入权或开放状态 |

800 m 用于公交站与超市，1,000 m 用于诊所，是已批准的工作参数，用来规定“多大的邻域内算一个选择”。目前没有问卷或行为校准证明这些半径最适合学生，也没有证明 1,000 m 医疗邻域比 800 m 更正确。住宅与设施中间可能有高速路、围墙或水道，圆内不保证走得到；也不应把圆半径直接写成某个步行分钟。

教学边界例子：超市在 799 m 或恰好 800 m 都计 1，在 801 m 计 0。此硬边界有助于复算，却可能放大邻域边缘的小坐标误差。未来可比较多半径或距离衰减，但它们尚未进入冻结结果。真实零计数保持 0；若整个设施源缺失，则值是未知，不能说“周围没有设施”。

**分清两个问题：** 欧氏距离／网络距离回答“距离怎样量”；固定半径／距离衰减回答“设施随距离怎样计入”。两者是不同层次。距离衰减也可以使用欧氏距离，例如假设每500 m贡献减半，再将各设施贡献相加；500 m在下面只用于教学示意，未进入当前指标或实验。

## 6. 原值如何变成 0–1：同一把尺子一直使用

分钟、米和站点数不能直接相加。每个指标 j 先在**样本 A 的已观测、有限、非负原值**上计算 P5 与 P95，记为 `L_j`、`U_j`。校园列只使用 `Success` 路线；其他静态列按自身可用原值拟合，并非先删掉全部不完整行才统一拟合。P5 是约 5% 观测值位于其以下的分位数，P95 类似。

| 指标 | 固定 P5 | 固定 P95 | 方向 |
| --- | ---: | ---: | --- |
| 校园分钟 | 28.125833 | 87.501667 | cost |
| 轨交出口米 | 117.219198 | 1,552.803871 | cost |
| 公交站数 | 11 | 48 | benefit |
| 超市服务地址数 | 0 | 7 | benefit |
| 图书馆米 | 385.542751 | 3,036.189039 | cost |
| 诊所服务地址数 | 1 | 30 | benefit |
| 公园面米 | 32.246482 | 965.581336 | cost |

先裁剪：`x*_ij = min(U_j, max(L_j, x_ij))`。再标准化：

- benefit：`z_ij = (x*_ij − L_j) / (U_j − L_j)`；
- cost：`z_ij = 1 − (x*_ij − L_j) / (U_j − L_j)`。

这样所有 `z` 都是越大越好。P5/P95 裁剪限制极端值对尺度的影响；超过 P95 的 benefit 都得到 1，低于 P5 的 cost 都得到 1，因此它有意丢失尾部差异。**1 是本版尺度上的饱和值，不是服务完美、满意度 100% 或成功概率。** 原值始终保留。

例如真实示例中的公交站 57 个超过 P95=48，得到 `z=1`；站点 48 个和 57 个的这一项分数相同。校园 65.95 分钟的表现值为 `1 − (65.95 − 28.125833)/(87.501667 − 28.125833) = 0.362970`。未知、负数或非有限原值不变成 0；路线失败也不视为 0 分钟。若某列 P5=P95 或无法定义，程序报错要求处理，避免默默制造一个分数。

**再说直白一点：** P5与P95像尺子的两个端点。公交11站对应0分，48站对应1分，中间按比例换算；少于11站仍是0分，多于48站仍是1分。校园分钟是成本型，方向相反：短于约28.13分钟在该项饱和为1，长于约87.50分钟饱和为0。裁剪没有删除两端各5%的住宅，也没有改掉用于40／60分钟硬约束的原始分钟。分位数采用线性插值，可能不是某条实际观测值。

若用户提供七项 importance `a_j`，核心先校验有限、非负、不是布尔值且不能全为 0，然后用 `w_j = a_j / Σ_k a_k` 归一化。计算实现先除以最大值以避免大数溢出，数学上等价。例如 importance `(5,3,2,3,2,2,3)` 总和 20，恰好得到均衡向量。权重表示在已经统一尺度后如何取舍，不能直接理解为“校园节省 1 分钟值多少钱”。即使某权重为 0，本版仍要求该点七项测量完整。

点分数公式为 `S_i = Σ_j w_j z_ij`，第 j 项贡献为 `C_ij = w_j z_ij`。这是一种允许补偿的加权和：在没有触发硬约束时，一个方面较差可能由其他方面较好抵消。相关的交通或市中心设施指标还可能重复表达相似优势；相关图能提示这种风险，不能自动解决概念重叠。

**相关图怎么读：** 每个格子比较两列在相同代表位置上的共同变化。正相关表示常一起变大，负相关表示一大一小；图例给出−1到1的尺度。对原始指标，“更大”未必“更好”（距离越大反而越差），不能只看颜色就删指标。

## 8. 从点到 Subzone：先看资格，再平均，再排名

一个点的七项均完整且目的地受支持才是 `valid`。有效且通过原始通勤分钟上限（若启用，`t_i ≤ cap`）才是 `feasible`。未查询、NoRoute 或技术失败都是未验证，不能当作零分钟，也不能默认通过上限。

设一个区域有 `N` 个计划位置，`V` 个有效位置，`F` 个可行位置：

- `valid_share = V/N`，反映测量覆盖；
- `conditional_feasible_share = F/V`（V=0 时为空），描述已有效位置中的可行比例；
- `verified_feasible_share = F/N`，反映全部计划位置中已验证可行的比例。

正式资格是 `V/N ≥ 0.90`、`F/N ≥ 0.50`、`F>0`。**分母是计划数 N**，不能删去失败行后用 F/V 代替。教学假设：20 个计划点中 18 个有效、9 个满足上限，覆盖是 90%，条件可行率是 50%，但已验证可行率只有 45%，因此不合格。

<!-- VISUAL: eligibility -->

合格区域按其**可行点的等权平均分** `S_area = (Σ_{i∈F} S_i)/F` 排名，贡献同样取可行点平均。没有按人口、住房单元数或每栋楼加权，区域支持的大量原始记录也不会自动增加权重。例如两个可行点 0.8、0.6 得 0.7；第三个失败点不会作为 0 加入均值，但仍进入覆盖与资格分母。某个不合格区域仍可能有可计算的均分，不能只看该列给它排名。

并列时依次用：分数降序、可行点平均原始校园分钟升序、平均原始轨交出口距离升序、`unit_id` 字典序。只有合格区域有名次，返回最多 5 个不同区域；不足 5 个就如实返回，不能补造。`limited_support = n_valid < 3` 是少样本提示，不会自动剔除候选。

实际 A 有效点 2,170/2,176，默认合格 Subzones 为 239/241。ONE TREE HILL 为 4/5=80% 有效，SENTOSA 为 10/15≈66.7%，均未达到 90% 覆盖；它们不是“零分地区”。正式 Top 5 为：

| 2 | CHINA SQUARE | 0.879429 | 1 / 1 / 1 | 是 |
| 3 | CHINATOWN | 0.867704 | 6 / 6 / 6 | 否 |

**5 个入选区域中 4 个只有 1–2 个有效样本。** PEOPLE'S PARK 的均分等于唯一代表点分数；这不证明区域内所有房屋、居民或可租房源都一样优越。源候选支持和采样密度都应与分数同时展示。

Monte Carlo 用 **1,000 次**随机权重探索均衡附近的偏好变化：`w^(b) ~ Dirichlet(κ w_balanced)`，`κ=50`，`seed=42`。参数向量为 `(12.5,7.5,5,7.5,5,5,7.5)`。每次权重非负且和为 1，其期望是均衡权重；κ 越大通常越集中。本版的 κ 和分布不是从真实学生偏好估计出来的，seed 只是复现随机序列的设置。

每次重算全部区域排名，保存权重与结果。区域入选频率为 `Σ_b 1[rank_b≤5]/1000`，名次中位数、P5、P95 来自有定义的名次；名次越小越前。未知名次保留空值。原本不合格区域在这个只改权重的实验里仍不合格，频率为 0，不能给空名次补 0。

| PEARL'S HILL | 0.174 | 7 | 5–10 |

## 10. OAT：找出哪些偏好区间会改变名单

OAT（one at a time）每次只指定一个目标指标权重 `t`，其余权重按原均衡比例共同缩放。对目标 j：`w'_j=t`；对 `k≠j`：`w'_k = w_k × (1−t)/(1−w_j)`。这样总和始终为 1，其余六项之间的比例保持不变。若校园从 0.25 改成 0.35，其余每项乘 `0.65/0.75`，例如轨交从 0.15 变为 0.13；不能只把校园改大却让总和超过 1。

每个指标用 `0.05,0.10,…,0.60` 共 12 个目标值，7×12=**84 组**。每个指标相邻 11 段，7×11=**77 个相邻区间**。其中 **17 段的 Top 5 集合发生变化**：校园 4、轨交 1、公交站 4、超市 3、图书馆 2、诊所 2、公园 1。

真实例子：校园权重 0.30 时第 5 名是 BOAT QUAY（0.821331）；0.35 时第 5 名变为 CLEMENTI CENTRAL（0.818988），前四个名单相同。因此这两个端点的 Top 5 Jaccard 为 `4/6=0.666667`。这只把变化定位在测试区间 0.30–0.35，**没有求出精确临界权重**，也不表示区间内恰好只有一次切换。另一个实际变化发生在校园 0.05→0.10，CLARKE QUAY 被 TANJONG PAGAR 替换。

OAT 仍是 A/Subzone、无上限和固定标准化，只探索七条规定路径，不能代表整个七维偏好空间。逐段证据见 [oat_switch_intervals.csv](../../outputs/experiments/oat_switch_intervals.csv)，具体权重和区域名次见 [OAT 权重](../../outputs/experiments/oat_weights.csv) 与 [OAT 名次](../../outputs/experiments/oat_ranks.csv)。

**与Monte Carlo的区别：** Monte Carlo让各项一起随机改变，观察整体偏好扰动；OAT沿一条明确的调整路径，帮助定位“哪项重要性提高时名单会变”。两种方法回答不同问题；都不能证明指标本身概念合理或数据准确。

## 11. 路线分钟的特别含义：必须随图表一起交接

本版对 **2,196 个不同起点**完成同一场景查询，2,190 条 `Success`、6 条 `NoRoute`。A 中是 2,170 条成功与 6 条无路线；NoRoute 未补 0，也不证明现实没有公交。起点、目的地坐标、时刻、模式和适配器版本都用于场景验证与缓存；不能将 B 的演示分钟或另一天的路线混入。

指标取提供者返回的**第一条 itinerary 的 `duration/60`**，不额外搜最短方案，也没有因结果难看而换掉长步行案例。`TRANSIT` 是请求模式，不保证回答一定乘公交／轨交。独立 AI 桌面复核的 20 条有效行程中，4 条只有 WALK：Clementi Woods（403 m / 4.85 min）、Pasir Panjang 1 landed（1,073 m / 12.88 min）、其 non-landed 案例（736 m / 8.83 min）、Clementi West（2,072 m / 24.85 min）。这解释了为什么一些“校园分钟”很短，但不能写成这些人实际乘坐了公共交通。

请求带有 `maxWalkDistance=1000`，复核仍发现 5 条有效行程含单段步行超过 1,000 m，且提供者 `walkLimitExceeded=false`。Sentosa 例首段 2,409.99 m / 32.30 min，总步行 2,753.68 m。参数和该布尔值都不足以保证严格步行上限；总步行超过 1,000 m 与某一段超过 1,000 m也不是同一个判断。

**08:00 到行程开始的初始等待可能不含在 duration 中。** 桌面样本里的乘车行程比请求时刻晚 64–765 秒开始。真实 Sembawang Straits 案例于 08:12:45 开始、10:03:31 到达，存储行程时长 110.77 分钟，而从 08:00 到到达为 123.52 分钟；Sunset Way 是 16.93 与 23.17 分钟。`waiting_min=0` 也不能解释为请求后不需等车。当前 40/60 分钟硬限制作用于冻结的 itinerary duration，并非“从 08:00 起到门口”的完整耗时。

AS8 坐标经过官方资料与真实返回路线的桌面审阅，仍只是建筑级**地面到达代理**。复核最终步行几何终点距配置点约 12.44–13.38 m，不构成测绘门口、无障碍入口、室内、电梯或教室到达认证。简短站内连接也不能当成人行平台换乘实测。

路线证据是 **21 个案例：20 个有效行程＋1 个无行程响应；15 个 reviewed_acceptable、6 个 reviewed_concern**。审查由独立 AI 上下文读完整分段、时刻、几何与组成，复查来源仍是 OneMap；“独立”指审阅过程，并不是独立路线提供者。无行程案例保留，追加 Sunset Way 才达到 20 个有效行程。没有完成同场景其他提供者旅行时间对比，也没有人工实地乘车计时，不能算路线准确率或独立实证验证。[完整桌面审查](../route-desktop-review.md) 与 [AS8 终点说明](../as8-endpoint-review.md) 应随结果共享。

| 50%（默认规则） | 167 | 同上 |
| 75% | 152 | 同上 |

这里“Top 5 不变”只说明名单对这三个门槛不敏感；合格集合已经从 178 变为 152，不能说资格规则无影响。25/50/75% 都是明确声明的推荐政策参数，不是调查所得的学生接受比例。详见 [cap40](../../outputs/experiments/commute_cap_40/)、[cap60](../../outputs/experiments/commute_cap_60/) 和 [资格对照](../../outputs/experiments/qualification_comparisons.csv)。

## 13. 三臂空间敏感性：分开观察补点与区域尺度

三个空间臂都固定**均衡权重、60 分钟上限、A 的标准化参数和同样资格规则**，这样每次对比才有明确解释。

| 臂 | 计划位置 | 区域单位数 | 合格数 | 改变了什么 |
| --- | ---: | ---: | ---: | --- |
| A_subzone | 2,176 | 241 | 167 | 原采样与官方分区 |
| B_subzone | 2,196 | 241 | 167 | 增加 20 个漏簇覆盖点，仍用相同分区 |
| B_cluster | 2,196 | 384 | 276 | 保持 B 位置，改用分析簇汇总 |

A_subzone 与 B_subzone 可按同一 Subzone ID 比名次。两者 Top 5 完全相同，Jaccard=1；167 个共同合格区域 Spearman=0.999480、Kendall=0.993363，但 CHINATOWN 均分从 0.867704 变成 0.869919，说明“名单相同”不意味着全部数值相同。

B_cluster 的实际 Top 5 是 PEOPLE'S PARK `39fc69d26fca`、TANJONG PAGAR `df3846d8096e`、PEARL'S HILL `3f0b940407d7`、CHINATOWN `1064ecff3b71`、CHINATOWN `c03a99682846`。它们是 5 个不同分析簇，可以有 2 个来自 CHINATOWN；不能宣称这等于 5 个不同 Subzones。

Subzone ID 与 cluster ID 不是同一候选实体，不能跨类型直接算 Spearman、Kendall 或 ID Jaccard。实现将两份 Top 5 推荐展开到**共同 B 位置集合**，并另外展开到**全量候选建筑／地址来源记录集合**：

- B_subzone Top 5 包含 13 个计划位置，B_cluster Top 5 包含 5 个，交集 4 个、并集 14 个，位置 Jaccard=`4/14=0.285714`；
- 全量候选记录分别为 64 与 17 个，交集 16、并集 65，建筑记录 Jaccard=`16/65=0.246154`。

这使用完整成员表，而非把 13 与 5 个样本点误叫成全部住宅。64 或 17 仍是候选来源记录数，不是住户、床位或可租数量。真实尺度对比如下：

| 入选单位 | 计划位置 | 全量候选记录 | 包围盒对角线 |
| --- | ---: | ---: | ---: |
| B_subzone CHINATOWN | 7 | 44 | 1,282.52 m |
| B_cluster CHINATOWN `c03a99682846` | 1 | 11 | 319.88 m |
| B_cluster CHINATOWN `1064ecff3b71` | 1 | 2 | 111.28 m |
| B_subzone CHINA SQUARE | 1 | 9 | 169.31 m |
| B_cluster PEOPLE'S PARK `39fc69d26fca` | 1 | 1 | 0 m |

全部 5 个入选 cluster 都只有 1 个有效位置。较小单位更容易形成高分、低内部差异、低样本支持的局部推荐；大分区平均则可能遮住内部差异。低重叠说明“推荐所覆盖的地理对象随尺度改变”，**两种尺度不足以证明哪种更好，也不能单凭低 Jaccard 判定模型失败**。边界效应、150 m 阈值、400 m 网格、全量路由或更多采样的扩展均可另作检验。[空间对照 JSON](../../outputs/experiments/spatial_comparison.json) 和各臂 [支持表](../../outputs/experiments/spatial_B_cluster/selected_unit_support.csv) 保留精确数值。

## 14. 哪些证据已完成，组员怎样使用与复算

冻结实现已有 117 项测试通过、mypy 与 ruff 通过，规范和实现由分离审阅上下文检查。真实 A 的 2,170 个有效点和全部 241 个区域的独立标量算术核对最大差为 2.22e-16；同输入重跑的点分数、区域分数、Top 5、元数据四份文件逐字节相同。另有 31 个真实静态／聚类抽查案例、1,000 次权重和全部保存实验的独立核对。此段报告的是 [已有验证记录](../verification.md)，不是声称每次打开本文都重新跑了全部验证。

这些证据支持“程序按声明规则算、算术可复现”。它们不认证全部住房用途、设施开放、实际乘车分钟或学生偏好。数据快照仍为 `production_ready=false`；分数可以精确到很多小数位，概念与数据的不确定性仍然存在。

地图、网页或 Agent 每次使用**同一 bundle** 的 `result_metadata.json`、`point_scores.csv`、`area_scores.csv`、`top5.csv`，核对相同 `result_id`。默认在 [outputs/score](../../outputs/score/)；实验各自有目录。点表保留所有计划行及原值、标准化值、状态、贡献；区域表保留覆盖、可行比例、少样本提示和名次；元数据保存版本、权重和阈值。不要只取一张 Top 5 表就丢掉资格与限制。

网页选择器切换已经保存的情景，40/60 分钟保存的是均衡版本。未支持的校园或组合应明确说明没有已计算结果。需要新权重、阈值或校园，应由核心生成新的独立 bundle；前端不能自行补缺失、改公式或把分数当概率。

标准完整包同时包含 [raw_data](../../raw_data/)：176 个原始交付副本文件，共 625,191,511 bytes，含 A/B 原始 ZIP 与解压内容，复制完整性由文件 hash 核对。Notebook 默认读取这个目录。GitHub 源码仓库不包含这些原始文件，单独从 GitHub 取得代码的组员需另取完整包或提供相同原始交付；历史旧包也不能据此宣称已有完整原始数据。派生 `outputs/prepared` 与原始 `raw_data` 应分别保留。

标准包的 Notebook 用于按顺序读取现有输入、讲解与重算；已有评分重算不需 OneMap token，新增指定场景路线才需本机凭证。重跑原始 prepare 时将 `raw_data` 作为数据根目录。安装与命令见 [根 README](../../README.md)，字段契约见 [interfaces.md](../interfaces.md)。开始新版本前，先复制／保留当前输出与元数据，确认复算目标。

## 15. 按重要性讨论的下一步，以及可采取的方案

1. **先统一通勤变量的产品含义。** 当前结果可如实称“首条计划行程 duration”；若用户真正关心“08:00 到实际到达”，可在新版本增加请求时刻到 arrival 的分钟。若只接受乘车方案，可新增纯步行标记或另设约束；若要严格步行上限，需检查返回各段后显式判定。用现有长步行、纯步行、初始等待例子对照新旧 Top 5，避免看到排名后才挑路线。
2. **再处理少样本推荐。** 可保持当前资格并强化样本／候选支持显示，或预先声明最小有效样本门槛，或对入选与边缘区域加密代表点。不同方案会改变 PEOPLE'S PARK 等小区域资格；不能把高频入选当成少样本问题已解决。先检查来源住宅用途与可租适用性，尤其是候选记录极少的中心区域。
3. **完成住宅、设施与运营核准。** 与 A/B 逐组裁定 107 个邮编冲突；核准医院／超市不完整单元、疑似编码错误与共址规则；审阅 455 个暂纳入绿地类别、公众开放和入口；补齐保留交通点运营审查。新证据要落到记录级审计，不能只在报告里写“已验证”。规则变更需更新数据版本与标准化依据。
4. **增加真正独立的出行证据。** 先按同起终点、同日期时刻、同模式冻结抽样，再记录另一提供者完整行程或安排人工计时；保留差异和无结果。独立来源比较、现场观测与本次 AI 同源桌面复核要分别标记，不能互相替代。
5. **核准偏好与补偿规则。** 可用清楚标注的用户 importance；也可另做学生调查、AHP 或其他偏好获取，但应有真实过程和结果。讨论相关指标是否重复加权、是否需要租金或住房供给指标；新指标会改变问题定义与数据需求。
6. **再扩展空间与测量假设。** 预先注册 250/500 m 采样、多半径、距离衰减、真实步行网络、公园入口、不同聚类阈值及校园。控制其余条件逐项比较；更多路线和原始来源可用性决定可做范围，现有两种尺度不替代这些检验。

所有这些方案都可以讨论，但**本交接不擅自替换冻结分数、数据版本或路线快照**。每次决定修改，应记录问题、证据、参数、采样和版本，在新目录保存完整 bundle，并把旧版与新版的资格、Top 5、贡献与地理支持并排比较。组员可根据这里的实际证据撰写最终报告，并披露 AI 用于代码、图表、测试和桌面复核的范围。
